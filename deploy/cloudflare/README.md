# Cloudflare Workers + D1

One Worker serves the dashboard assets and `/api/*`; no VPS or separate Node
server is required. D1 holds users, sessions, passkeys, policy state, audit events,
and rate limits. The landing page remains a separate frontend.

## Local development

```sh
bun install --frozen-lockfile
bun run --filter @tenet/dashboard build
# Copy apps/worker/.dev.vars.example to .dev.vars and set a random auth secret:
openssl rand -hex 32
bun run auth:admin migrate --worker
bun run auth:admin setup --worker
bun run dev:worker
```

Open `http://localhost:8787` and use the printed setup code. No Cloudflare account
is needed for local D1. A frontend change needs a rebuild, or use the dashboard's
Vite dev server with `TENET_API_URL=http://localhost:8787` and set the Worker's
`TENET_ORIGIN=http://localhost:3000` for that development arrangement.

## Deploy your installation

These commands create/deploy resources only when you run them:

```sh
bun run --filter @tenet/worker exec:wrangler d1 create tenet
```

Put the returned database ID in `apps/worker/wrangler.jsonc`. Set `TENET_ORIGIN`
to the final public HTTPS origin, configure its Worker route/custom domain, then:

```sh
bun run --filter @tenet/worker exec:wrangler secret put BETTER_AUTH_SECRET
bun run auth:admin migrate --worker --remote
bun run --filter @tenet/dashboard build
bun run --filter @tenet/worker exec:wrangler deploy
bun run auth:admin setup --worker --remote
```

Use a secret generated by `openssl rand -hex 32`. Never commit it or put it in
`vars`. D1 schema migrations and the application version must be deployed together.
The placeholder database ID intentionally requires an operator's configuration
before a real deployment. `bun run --filter @tenet/worker build` is a dry run.

Run `auth:admin cleanup --worker --remote` periodically. Back up D1 and the secret.
See [authentication](../../docs/authentication.md) for recovery and security details.

## Machine enrollment

Apply migration `0002_machines.sql` through the existing migration command. Before
building the dashboard, run `bun run bundle:daemon` on a build machine with Docker
and include the generated `apps/dashboard/public/daemon/` artifacts in your build
context/deployed assets. Git-only deployments do not include these gitignored
artifacts automatically. The panel must have a public HTTPS origin; `/api/*` and
`/daemon/*` must be reachable by the VPS. See [connecting machines](../../docs/machines.md).
